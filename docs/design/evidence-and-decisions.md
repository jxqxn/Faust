# 证据、决定与纠错账

2026-09-14。当前产品决定见[下一阶段契约](next-stage-handoff.md)，外部主张和数字见[研究总报告](../research/faust-game-design-data-research.md)。本页管理“哪些话可以怎样使用”。

## 1. 证据等级与有效性

用户决定、成品/源码事实、开发者口述、社区资料、项目解释、候选与未知事项分别保留。认可方向不等于验证了参数；作者说过不等于证明完整历史；市场成功不识别单个机制效果。遇到冲突查较晚明确决定及其范围，旧文自称“最高权威”不产生额外权力。未反对不等于确认；工具提醒、助手复述和用户引用供讨论的长文不自动成为用户决定。

## 创新试验记录规则（2026-09-15）

用户本会话确认：进入创新前固定复刻基线，独立分支试验，保留原作证据和失败经验。基线与操作方法见[下一阶段契约](next-stage-handoff.md)。这项决定不意味着已选定名册、组队或任何具体机制。

每项试验在本节追加一个有编号的记录，详细论证链接至机制或美术专题；失败记录保留，状态改为撤回或替代，不删除其依据。

| 必填字段 | 记录内容 |
|---|---|
| 编号、状态与问题 | 待验证/进行中/保留/撤回/被替代；一次只检验一个核心问题 |
| 基线与原作依据 | 使用的底座提交、METHOD_MAP条目、源码/配置/存档证据；原作未知部分明确标为未知 |
| 创新与理由 | 原作如何做、我们改变什么、预期改善什么；区分用户决定与助手建议 |
| 验收与反例 | 可玩经历、真实输入、状态变化、后续影响、存档恢复、可能证明假说不成立的结果；体验证据与程序正确性分开 |
| 结果与去留 | 实际观察、证据路径、限制、保留或撤回的原因；未做的实验不能写成已验证 |
| 代码与恢复 | 实现提交、后续撤回提交、存档兼容/迁移边界；从何处重新开始 |

当前尚无正式创新试验结果。不得把过往建议、原作对拍或这次基线保护写成创新体验已成立。

## 4. 未决事项需要什么证据

| 问题 | 已有材料 | 还缺什么 |
|---|---|---|
| 减手牌而不减人物意义 | 库存经济、名册、默认安排 | 搜索/误操作/人物复述对照 |
| 不卖人如何保持转换空间 | 圣兽编队、装备与条件 | Faust 供给、保留、退出成本与反例 |
| 成型后继续做什么 | 做牌、成长阵容、自动循环 | 实际输入与有意义选择，不能无限加数字 |
| 内在意志不抢玩家判断 | 极乐迪斯科与单角色研究 | 可解释冲突与干预边界 |
| 艺术方向怎样成立 | 否决方案与作品优先方法 | 成立作品及普通资产实测 |
| 独立产品是否有市场 | 邻近成功与困难案例 | 受众、定位和本项目体验验证 |

## 5. 覆盖、归档与维护

检索了 Faust 目录对应的 58 条 Codex、8 条 ZCode 任务元数据，并以关键词检查其他目录相关标题；提取其中 10 条 Codex 与 8 条 ZCode 的 user/assistant 文本。纯复刻、排障、自动审批转录和无关素材/LoRA 不编入原创成果。ZCode user 角色还含工具提醒，必须进一步过滤。

这是可访问本地记录的覆盖，不是所有平台/网页会话的全量证明。美术导入包有已保存材料，原网页逐轮对话未全部取回。全部旧设计/研究正文、机器方法数据及历史原型文档按原字节归档，清单登记 SHA256、章节、原路径和去向。章节映射不表示每个旧论点均已通过，仅在归档出现的参数和方案不得当当前决定。

正式区维护产品契约、机制、美术、本账及详细研究总报告。旧材料仅保留于 Git 历史中的单一 ZIP，工作区已删除该副本，**无当前指令效力**。新增讨论整合对应章节，避免再造多个“最终方案”。运行 tools/check_design_research.ps1 与 tools/check_innovation_archive.py 核验引用、快照和归档完整性。
