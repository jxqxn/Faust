# 《大骑士物语》：图板棋子结构的表现参照

> 状态：竞争作品机制研究入口；为 Faust 横版场景的"图板棋子结构"建立事实边界。它主要回答
> **表现与交互**问题（队伍如何在桌游式地图上被呈现和调度），不是校园自走棋的机制答案。
>
> 整理日期：2026-08-14
>
> 证据入口：公开事实与来源局限统一登记在
> [`faust-game-design-data-research.md`](../research/faust-game-design-data-research.md) 的
> `GK-*` 主张与来源中。

## 1. 新会话先读结论

《大骑士物语》（Grand Knights History，2011，PSP，Vanillaware 开发、Marvelous 发行）是
Faust 横版场景的**结构参照**之一：它把"队伍在插画桌游地图上移动"表现为**一个物理棋子走过
棋盘**——探索阶段队伍以棋子形态出现在大棋盘上，每任务有有限步数，不同格位触发事件、物品
或战斗（[`GK-RULE-001`]）。

它验证的是**表现层**：把空间、移动和位置决策压缩成"棋子 + 棋盘 + 有限步数"这一可读形式。
它没有验证校园自走棋的机制循环——它自己就是回合制战斗 + 在线领土战的组合。

> 《大骑士物语》验证了"图板棋子结构"的呈现方式，没有验证它承载的玩法循环。

## 2. 为什么它与 Faust 高度相关

Faust 横版场景的定位是"表现与交互探针"（见
[`autobattler-campus-direction.md`](autobattler-campus-direction.md)）。场景参考明确点名了
《大骑士物语》的图板棋子结构（见
[`thought-world-visual-references.md`](thought-world-visual-references.md)）：

> Grand Knights History remains the structural reference for a physical pawn moving
> through an illustrated tabletop map.

大骑士物语的图板结构提供了一种可读的空间语法：

```text
队伍 = 一枚物理棋子
地图 = 插画棋盘（区域、城镇、道路）
移动 = 有限步数（步数即资源）
位置 = 事件/物品/战斗的触发器
```

这与 Faust 横版场景"世界位置承载交互、出口与位置恢复"的既有工程（横版主场景 + 近距交互 +
场景出口 + 位置恢复）在**可读性目标**上同构：让"我在哪、我能去哪、这里有什么"一眼可读。

## 3. 已由公开资料确认的结构

### 3.1 探索：棋子 + 棋盘 + 有限步数（[`GK-RULE-001`]）

- 玩家带领最多 4 名自定义角色（骑士/弓箭手/法师三类）的佣兵团，效力于三国之一；
- 探索阶段**队伍以一枚棋子形态**在大棋盘上移动；
- 每个任务有**有限步数**，不同格位触发事件、物品或战斗；
- 完成任务解锁新区域。

这是"图板棋子结构"的直接来源：队伍不是以"一群人在地图上走"呈现，而是**压缩为一枚棋子**，
空间决策（去哪、绕路还是直行）由步数预算驱动。

### 3.2 战斗：Battle Sphere Reel + AP（[`GK-RULE-002`]）

- 战斗在凸网格战斗区（"Battle Sphere Reel"）进行，镜头随角色行动平移；
- 回合制：每回合开始选择行动（普攻/技能/治疗）；
- 行动消耗 AP，AP 每回合补一定量或击败敌人补充。

### 3.3 成长与死亡（[`GK-RULE-003`]）

- 重复使用特定技能/武器解锁新技能（熟练度式成长）；
- 装备武器/防具/装饰提升属性并改变外观；
- 死亡单位移出战斗、得一半 EXP、战后 1 HP 回归；全灭则游戏结束。

### 3.4 在线领土战（已关服）（[`GK-RULE-004`]）

- 在线多人：代表三国之一进行领土扩张战；
- 胜者投票决定下一攻击目标；个人角色可交由 AI 托管；
- 服务器 2013-10-31 关闭，在线时代行为数据不可复得。

### 3.5 概念延续：《Grand Kingdom》（[`GK-RULE-005`]）

导演 Tomohiko Deguchi 将概念延续到 2014/2016 的《Grand Kingdom》：

- 棋盘式地图 + 有限步数；
- 17 种雇佣兵职业，三主类型 Fire Emblem 式克制；
- 侧视三层平面战斗（类似 Guardian Heroes）；
- 手动瞄准：远程类 Worms、近战类清版；**有队友伤害**（误射、治疗扔错）；
- 派系在线 meta 战（投票战术、经济支持）。

## 4. 与 Faust 当前方向的差异

| 维度 | 《大骑士物语》 | Faust 横版场景的未决问题 |
| --- | --- | --- |
| 呈现 | 队伍压缩为一枚棋子 | 主角是移动棋子，NPC 在场景中具名存在 |
| 空间决策 | 有限步数预算（任务级） | 自由移动 + 出口（已实现）；步数资源未定义 |
| 位置语义 | 格位 = 事件/物品/战斗 | 场景位置 = NPC 交互、出口、恢复（已实现） |
| 战斗 | 独立回合制战斗区 | 校园自走棋自动对局（未实现） |
| 多人 | 在线领土战（已关服） | 单机，无 PvP 计划 |

这张表说明：大骑士物语贡献的是**"棋子 + 棋盘"的呈现语法**，不是战斗或成长系统的移植对象。

## 5. 启示与反例

**启示**：图板棋子结构把"队伍在哪、还剩几步、下一步去哪"压缩为单屏可读信息。Faust 横版
场景已实现主角移动与位置恢复；大骑士物语提示的下一步是**让位置承载更多可读语义**（此处有
什么、走到这里会发生什么），而不是增加地图复杂度。

**反例（必须主动构造）**：

1. 如果棋子只是"会走路的光标"，图板结构退化为菜单导航，失去"物理棋子"的实体感；
2. 如果步数预算变成强制限制（大骑士物语的任务级限制），可能违背横版场景"自由探索"的
   探针定位——步数限制是任务结构，不是场景表现；
3. 大骑士物语是单队伍棋盘，Faust 是具名角色群——多个角色如何在同一场景呈现而不退回
   "一堆图标排队"；
4. 在线领土战依赖长期运营，Faust 单机定位不应照搬在线 meta 结构。

## 6. 正确位置

大骑士物语在 Faust 研究体系中的位置是**表现与交互探针的结构参照**（与
[`thought-world-visual-references.md`](thought-world-visual-references.md) 一致），
与圣兽之王的手绘画面参考并列，但**不是**机制答案：

- 圣兽之王：手绘奇幻画面、场景纵深与编队表现；
- 大骑士物语：图板棋子结构（队伍 = 棋子、地图 = 棋盘、步数 = 资源）。

两者都只验证"看起来/走起来像什么"，不验证"玩起来成立什么"。

## 7. 对 Faust 的直接约束

后续场景方案引用《大骑士物语》时，至少回答：

1. 主角作为"棋子"在场景中移动时，位置如何承载可读语义（谁在这、会发生什么）？
2. 步数是表现的一部分，还是必须成为机制资源？如果是机制资源，它与手牌/仪式负担如何区分？
3. 多个具名角色在同一场景中如何呈现——单棋子（队伍合一）还是多棋子（各自在场）？
4. 场景的"棋盘感"是否与已实现的自由移动 + 近距交互冲突？
5. 引用图板棋子结构时，是否只是视觉相似，还是真的改变了空间决策的可读性？

任一问题的答案若只是"画面像大骑士物语"，则不构成场景方案。
