# 《这就是警察》：资源卡填入事件槽的血统参照

> 状态：竞争作品机制研究入口；为《苏丹的游戏》主创亲述的玩法血统建立事实边界。它是 Faust
> 理解"事件槽投入资源"语法的**血统参照**——不是校园自走棋的机制答案。
>
> 整理日期：2026-08-14
>
> 证据入口：公开事实与来源局限统一登记在
> [`faust-game-design-data-research.md`](../research/faust-game-design-data-research.md) 的
> `TIP-*` 主张与来源中。

## 1. 新会话先读结论

《这就是警察》（This Is the Police，2016，Weappy Studio）是《苏丹的游戏》主创远古之风
**亲述的玩法骨架来源**（[`TIP-EXPL-001`]）：

> 主创原话（经访谈转述）："我们的玩法与其说是密教还不如说是《警察故事》……借鉴了密教很多
> 地图叙事的逻辑，再加上《文明》式的'下一回合'的吸引力。"

它的核心语法是**把资源卡填入事件槽**：警员是资源，911 呼叫是事件，派遣=把资源投入事件，
通过选择和时间推进剧情（[`TIP-RULE-001`]）。苏丹的"仪式槽位投入卡牌"骨架由此而来，
**不是直接继承密教**——密教只贡献了地图叙事逻辑。

> 《这就是警察》验证了"事件槽投入资源"的结构可以承载叙事；它也是苏丹仪式的直接血统来源。

## 2. 为什么它与 Faust 高度相关

Faust 已复刻的仪式语法是：仪式提出槽位与条件 → 玩家从库存中找答案 → 满足配方并结算。
这条链的血统就是《这就是警察》的"事件槽 + 资源投入"（[`TIP-EXPL-001`]）。

两者的结构对应：

| 《这就是警察》 | 《苏丹的游戏》 | Faust 复刻底座 |
| --- | --- | --- |
| 911 呼叫（事件流） | 仪式/事件 | 仪式槽位 + 条件 |
| 警员（资源） | 人物/物品卡 | CardInstance |
| 派遣数量与技能选择 | 投入卡牌满足条件 | 拖入槽位结算 |
| 180 天倒计时 | 苏丹卡/期限 | 倒计时与期限 |
| 每天推进、等待计时器 | "点下一天"批量结算 | RoundLoop.advance_day |

理解《这就是警察》的原始设计（优点与缺陷），就是理解苏丹仪式骨架的起点。

## 3. 已由公开资料确认的结构

### 3.1 时间管理与倒计时（[`TIP-RULE-001`]）

- 玩家是 Freeburg 警察局长 Jack Boyd，被设定在 **180 天**内退休；
- 目标：180 天结束时攒够 **50 万美元**退休金（无养老金）；
- 每天推进，处理日益增多的 911 呼叫。

### 3.2 资源：警员 + 金钱（[`TIP-RULE-001`]、[`TIP-RULE-002`]）

- 主要资源只有两类：**警员**和**钱**；
- 两班制轮换（每两天换班）；
- 警员有**专业度**（Professionalism，平均值 150）与**技能点**（发命令消耗）；
- 警员有真实感状态：请假、醉酒上班等。

### 3.3 派遣与现场决策（[`TIP-RULE-001`]）

- 每次呼叫需派遣适当数量与技能水平的警员；
- 派完等计时器完成（时间管理节奏，被评测形容为"更像手游"）；
- 现场偶发有限选项决策（对现场警察下命令）。

### 3.4 风险升级与后果不透明（[`TIP-RULE-004`]）

- 故事推进后单人出警越来越危险，被迫权衡派多少人；
- 后果信息不透明：玩家难以判断哪些选择有严重后果，警员可能无预警死亡。

### 3.5 人员管理与关系网（[`TIP-RULE-003`]、[`TIP-RULE-005`]）

- 开除规则：无故开除引发法律纠纷；有正当理由（缺勤/醉酒/年龄/连续 3 次失败响应）才可开除；
- 与黑手党、市政厅、警局等维持关系，通过特殊任务派遣换取奖励（隐藏账户、安全开除等）。

## 4. 与 Faust 当前方向的差异

| 维度 | 《这就是警察》 | Faust 校园自走棋的未决问题 |
| --- | --- | --- |
| 投入对象 | 警员（匿名、可替换、两班轮换） | 具名角色（长期、有后果） |
| 事件性质 | 911 呼叫（数量压力） | 校园生活与关系（选择质量） |
| 时间结构 | 180 天固定倒计时 | 校园周期（未决） |
| 后果归属 | 警员死亡（资源损失） | 谁承担后果（人物责任，未决） |
| 叙事推进 | 选择 + 时间推进剧情 | 卡牌流转 + 仪式结算（已复刻） |

这张表说明：《这就是警察》贡献的是**"事件槽 + 资源投入"的骨架**，而 Faust 要在同一骨架上
回答"投入的对象是具名人物时，后果如何归属"。

## 5. 启示与反例

**启示**：

1. **事件槽投入是叙事载体**：把"决定派谁去"做成核心决策，叙事从资源分配中涌现——这是苏丹
   仪式的直接祖先，也是 Faust"把卡牌投放到结构化槽位"语法的来源。
2. **数量即压力**：呼叫越来越多、单人出警越来越危险——压力来自"资源相对于事件流不足"，
   而不是单个事件本身的复杂度。
3. **有限信息制造紧张**：后果不透明（哪个选择会死人）是设计选择，制造了道德紧张感——但
   评测也批评它伤害了可读性，这是"信息透明 vs 紧张感"的张力点。

**反例（必须主动构造）**：

1. 如果所有事件都只是"派多少资源"的数量题，人物会退化为可替换的数字（警员死了换一个）；
2. 后果不透明如果过度，玩家会把失败归因于"系统黑箱"而不是自己的决策——评测明确记录了
   这种挫败（警员无预警死亡且原因不可查）；
3. 计时器等待（派完等时间）如果直接移植，会变成手游式挂机，与 Faust 减少管理负担的目标
   冲突——苏丹已把它改造为"点下一天批量结算"；
4. 匿名警员的"开除换人"逻辑，不能平移到具名角色——后者要求后果跨局留存。

## 6. 正确位置

《这就是警察》在 Faust 研究体系中的位置是**血统参照**：它解释了苏丹仪式骨架从哪来
（[`TIP-EXPL-001`]，主创亲述），并提供了一个"事件槽投入"的原始样本。它与密教（
[`CS-EXPL-001`]—[`CS-EXPL-002`]）一起构成苏丹的两条血统：

- 密教模拟器：资源叙事 + 卡牌统一语言（地图叙事逻辑被苏丹借鉴）；
- 这就是警察：事件槽投入 + 时间推进（仪式骨架被苏丹借鉴）。

两者都通过主创访谈确认（[`CS-OFFICIAL-004`]、[`CS-OFFICIAL-005`]），是苏丹设计来源的
**已确认**证据，不是推断。

## 7. 对 Faust 的直接约束

后续方案引用《这就是警察》时，至少回答：

1. "把资源填入事件槽"在 Faust 中对应什么——卡牌填入仪式槽（已复刻）之外，校园生活是否
   也采用同类结构？
2. 当投入对象从匿名警员变成具名角色时，"派多少人"的数量决策如何变成"派谁"的人物决策？
3. 后果不透明的紧张感与"玩家能读懂失败原因"的可读性如何平衡——评测记录的挫败是反面教材；
4. 180 天倒计时式的整体期限，与苏丹卡/仪式期限（已复刻）的关系是什么？
5. 计时器等待节奏是否应保留——还是像苏丹一样用"点下一天批量结算"替代？

任一问题的答案若只是"事件流 + 派遣资源"，则不构成校园自走棋方案。
