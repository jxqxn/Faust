# 《苏丹的游戏》如何让卡牌资源成为人物叙事

> 状态：设计研究基线（2026-08-10）
>
> 用途：解释《苏丹的游戏》如何改造《密教模拟器》的卡牌与仪式语法，并据此约束 Faust 后续对自走棋、校园、养成和人物叙事的整合方式。
>
> 关联研究：[`fire-emblem-narrative-transformation.md`](fire-emblem-narrative-transformation.md)、[`sultans-game-cognitive-load-and-automation.md`](sultans-game-cognitive-load-and-automation.md)

> 关于《风花雪月》与 P5 谁更接近本作人物日程结构的比较，见 [`three-houses-p5-sultan-schedule-comparison.md`](three-houses-p5-sultan-schedule-comparison.md)。

## 1. 核心结论

《苏丹的游戏》确实完成了一次与《火焰纹章》相似的类型改造，但两者的方向不同：

> 《火焰纹章》把棋子变成了人。
>
> 《苏丹的游戏》先把人变成可调度的棋子，再让玩家通过持续后果意识到：棋子仍然是人。

《苏丹的游戏》并不是简单为《密教模拟器》“增加更多剧情”。《密教模拟器》本来就是叙事游戏；它真正完成的转译是：

> 把抽象、晦涩、知识考古式的卡牌叙事，改造成具名、连续、关系化、可追悔的人物叙事。

这次改造的核心公式是：

> 具名人物卡 × 核心流程中的实际用途 × 持续状态与关系 × 不可逆选择后果
>
> = 玩家亲手形成的宫廷史与道德史

苏丹卡、倒计时、资源紧张和生存压力会迫使玩家作出选择，但它们只是催化剂，不是这次叙事改造的本体。

## 2. 有开发者证据的设计谱系

双头龙工作室明确表示，《密教模拟器》系列和《这就是警察》是《苏丹的游戏》最重要的影响来源：

- 从《密教模拟器》继承把世界对象制成卡牌、再将卡牌选择性投入仪式的表现和操作语法；
- 从《这就是警察》借用地点导向、在城市中调配资源并铺陈剧情的基础结构；
- 早期曾设想更自由的卡牌合成，但开发者认为过度自由会喧宾夺主，损害剧情体验与事件之间的博弈，因此主动收缩组合自由，并明确以故事为主导。

这说明《苏丹的游戏》不是在《密教模拟器》之外另做一套视觉小说，而是在保留宿主语法的前提下重新规定卡牌、槽位和结算所承载的叙事意义。

## 3. 被保留的宿主语法

《苏丹的游戏》保留了以下核心结构：

1. 人物、物品、知识、压力和机会都作为卡牌存在；
2. 玩家持有、整理和调度这些卡牌；
3. 仪式或事件以槽位条件规定可投入对象；
4. 投入对象与当前状态共同选择结算分支；
5. 结算消耗、生成或修改对象，并打开或关闭后续可能性。

《密教模拟器》的创作者曾把卡牌描述为具有实体感、可以整理、会来去，并且“有意义但可被处置”的对象。卡牌可以表示人物、地点、书籍和行动，玩家通过组合与试验理解世界。

来源：[Game Developer 对《密教模拟器》创作者的采访](https://www.gamedeveloper.com/design/why-the-i-cultist-simulator-i-devs-built-their-lovecraftian-game-on-a-house-of-cards)

## 4. 第一次关键改造：抽象资源获得持续人物身份

《密教模拟器》中的人物仍主要服务于抽象属性、知识探索和配方试验。《苏丹的游戏》则让人物卡同时拥有：

- 姓名、肖像、身份和社会位置；
- 与主角及其他人物的关系；
- 自己的事件链与未来可能性；
- 会被后续条件读取的属性、品级、标签和装备；
- 会持续存在的成长、伤害、背叛、死亡与缺席。

因此，人物卡不再只是“满足某种数值的角色资源”。玩家在后续事件中再次遇到的，是先前被自己培养、伤害、拯救或利用过的同一个人。

## 5. 第二次关键改造：支付资源变成处置某个人

《密教模拟器》的典型问题是：

> 我需要投入什么对象，才能满足这个仪式或配方？

《苏丹的游戏》把它改写为：

> 我知道什么对象能够满足条件，但我要让谁承担这个结果？

杀戮不再只是支付一张符合品级条件的角色卡，而是杀死妻子、朋友、追随者或本来可能成为盟友的人。纵欲、征服等行为也会落在具体对象和具体关系上。

于是，同一次槽位投放同时回答两个问题：

- **策略问题**：这张卡是否符合槽位和结算条件？
- **人物问题**：玩家愿不愿意这样对待这个具体的人，并承担由此失去的未来？

这使资源优化本身成为人物叙事，而不需要切换到另一个独立剧情模式。

## 6. 第三次关键改造：后果必须回写同一对象和未来结构

原作配置和反编译结构共同显示，仪式并非只播放一段结果文本：

- 结算面板根据已投入对象及当前上下文选择匹配的 settlement 分支；
- 操作系统能够按过滤条件修改玩家持有的具体卡牌；
- `clean.sN` 等结算能够清除槽位所指向的具体对象；
- 人物身份和标签可以选择不同结果文本、计数器、事件与后续状态。

这里的设计重点不是某个单独 DSL 键，而是统一的对象链：

> 选择具体人物 → 将其投入行动 → 结算修改或移除该人物 → 未来内容读取修改后的世界

## 7. 第四次关键改造：善恶不是数值，而是未来的不同形状

双头龙工作室说明，他们不打算把善恶简单设计成奖励或惩罚，而是让每种选择得到符合自身逻辑的后续：

- 善意选择通常回报较慢，却会保留人物、关系和长期可能性；
- 恶意选择通常提供即时回报，却经常消费人物并终结相应事件链；
- 极端选择不应只是玩笑选项，故事仍需承认玩家确实做过这件事并继续发展。

因此，它的道德结构可以概括为：

> 善保留未来，恶消费未来。

玩家记住的不是抽象善恶值，而是“我为了活下去怎样对待了谁，因此后来失去了什么”。

## 8. 与《火焰纹章》的同构与差异

| 结构位置 | 《火焰纹章》 | 《苏丹的游戏》 |
|---|---|---|
| 原始抽象 | 可替换的战争单位 | 可投入配方的卡牌资源 |
| 人物化方式 | 姓名、职业、成长、阵亡 | 姓名、身份、关系、标签、事件链与死亡 |
| 玩家介入 | 培养、部署、救援、承担伤亡 | 选择具体人物投入仪式并承担结算 |
| 持续历史 | 单位保留成长与战场经历 | 人物保留状态，未来分支读取旧选择 |
| 玩家故事 | 每个人不同的战争史 | 每个人不同的宫廷史与道德史 |

二者最大的差异是作者性：

- 《火焰纹章》更偏向让人物故事从战术系统中自然生长；
- 《苏丹的游戏》更偏向让系统迫使玩家亲手介入作者编写的人物故事。

双头龙主动限制部分组合自由以保护剧情与事件博弈，说明它愿意用部分系统开放性换取人物叙事的可读性。这个取舍是它的具体方案，不是所有后继设计都必须照搬的原则。

## 9. 对 Faust 的确定约束

Faust 后续对自走棋的改造必须继承的不是苏丹卡题材，而是同一对象贯穿全部核心循环的原则。

同一名学生应同时是：

- 手牌中可以调度的角色卡；
- 课程、社团和校园行动的参与者；
- 自走棋阵容中的战斗单位；
- 会因上述经历持续变化的具体人物。

由此得到以下约束：

1. **不得只复用后端再另做一套校园 UI。** 人物叙事必须长在既有卡牌流转、槽位投放和结算反馈之中。
2. **成长必须回写同一人物实例。** 上场、落败、课程、关系与行动结果不能只增加局外货币或解锁一段文本。
3. **人物关系必须改变核心选择空间。** 关系应影响可进入的槽位、协同、阵容、行动代价或后续结果。
4. **重大选择必须改变未来。** 叙事结果至少应持续改变人物状态、可用组合、关系网络或事件入口之一。
5. **自走棋不能成为无后果的独立小游戏。** 对局前的培养与关系必须改变对局；对局中的使用与结果也必须反过来改变校园生活。
6. **压力机制不是必要前提。** 跨日、苏丹卡倒计时与随机事件可以改造或移除；只要人物选择和持续后果仍由核心卡牌语法承载，叙事转译就仍然成立。

最终要达到的状态不是“玩一会儿自走棋，再看一段角色剧情”，而是：

> 玩家怎样调度角色，就是角色故事怎样发生；角色经历了什么，又会改变玩家以后怎样调度他们。

## 10. 证据边界

### 已验证事实

- 开发者明确承认《密教模拟器》与《这就是警察》的影响，并说明采用故事主导、限制过度自由合成的取舍。
- 原作结算结构会根据投入对象与上下文选择分支，并能够修改或清除具体人物对象。

### 配置观察

- 多个仪式把具体人物身份、关系标签与苏丹卡同时作为槽位和分支条件；结果会修改人物、清除人物、生成卡牌、改变计数器或开启事件。

### 设计推论

- “先把人变成棋子，再证明棋子仍然是人”是对机制效果的总结，不是开发者原话。
- “善保留未来，恶消费未来”是对开发者所述回报结构的抽象。
- 苏丹卡与倒计时属于催化剂而非改造本体，是用于指导 Faust 取舍的项目判断。
