# 《圣兽之王》：自动战斗、具名人物与叙事的核心参照

> 状态：竞争作品机制研究入口；已补齐逐系统数值分析（§9，攻略级社区来源），为后续深入拆解建立事实边界，但不把《圣兽之王》直接登记为酒馆战棋式自走棋。
>
> 整理日期：2026-08-13；§9 逐系统数值分析于 2026-08-14 补齐
>
> 证据入口：公开事实、市场数字和来源局限统一登记在
> [`faust-game-design-data-research.md`](../research/faust-game-design-data-research.md) 的
> `UO-*`、`NAB-*` 主张与来源中。

## 1. 新会话先读结论

《圣兽之王》是 Faust 的**核心机制参照物**，而不只是美术参考。它已经证明：完整单机叙事、
大量具名人物、长期培养与自动执行的局部战斗可以共同构成一款商业成功的游戏。

但它不是严格意义上的酒馆战棋式自走棋。玩家仍在关卡地图上持续指挥部队移动、选择交战、
使用场上能力并争夺目标；自动化主要发生在两个小队接触后的局部战斗。它没有以随机商店、
购买出售、逐轮淘汰和高频替换阵容组成核心循环。

因此，后续引用时必须保持下面的边界：

> 《圣兽之王》验证了“具名人物叙事可以与自动战斗共存并成功”，没有验证
> “具名人物叙事自走棋”已经形成成熟市场范式。

## 2. 为什么它与 Faust 高度相关

《圣兽之王》的关键不是“战斗会自动播放”，而是它把玩家决策重新分层：

```text
长期层：招募、培养、装备、关系与军队组织
→ 编成层：把具名人物组成小队，安排前后排和功能互补
→ 指令层：为技能设定发动条件、目标偏好和优先顺序
→ 战场层：在关卡地图上选择路线、时机、交战对象与支援
→ 自动层：接敌后按此前配置自动执行局部战斗
→ 反馈层：根据结果调整编成、装备、指令和后续行动
```

这说明自动化并不一定删除策略。它可以把策略从“逐个输入攻击命令”迁移到“预先组织人物、
条件和责任”，再让执行结果成为玩家检验自己理解的反馈。

这与 Faust 当前假说直接相交：系统可以自动完成低价值的过程执行，但玩家仍需决定哪位具名
人物参与行动、以什么准备参与，以及由谁承担长期后果。

## 3. 已由公开资料确认的结构

### 3.1 具名人物不是战斗外的收藏页

官方资料明确以超过 60 名角色、不同背景的可招募同伴和自由编队作为卖点。人物同时存在于：

- 剧情与世界关系中；
- 招募和长期成长中；
- 小队编成、职业与装备中；
- 自动战斗的技能与行动规则中。

这对 Faust 的价值是：人物身份必须进入实际结算对象，而不能只在剧情界面具名、进入玩法后
又退化成匿名职业棋子。

### 3.2 自动执行建立在玩家可配置的因果链上

官方系统说明确认，局部战斗会依据玩家预设的“作战”自动进行；玩家在战斗前组合人物、装备，
并设置技能的发动条件。自动执行因此不是与玩家选择无关的演出，而是此前配置的结果展示。

后续深入研究时应重点拆解：

- 条件表达能力：系统允许玩家描述哪些目标、状态、顺序和例外；
- 冲突处理：行动资源不足、多个条件同时满足时如何决定优先级；
- 可预见性：玩家在开战前能看到多少结果信息；
- 诊断能力：失败后能否判断是编成、指令、装备还是战场选择的问题；
- 修改成本：调整一支小队需要多少页面、步骤和记忆。

这些问题目前尚未在本项目资料库中完成逐项配置提取或操作计时，不能把“看起来清楚”写成
已经测得的认知负荷结论。

### 3.3 自动战斗只承接局部执行

《圣兽之王》没有把整个战术过程都交给自动系统。玩家仍在实时推进的关卡地图中承担高层指挥。
这构成一个重要反例：

> 它的成功可能来自“把局部交战自动化、保留战场指挥”，而不是来自“自动化本身”。

所以 Faust 不能仅凭该作品成功，就推导出应当自动处理校园分配、仪式选择、人物承担者或所有
战斗层决策。我们必须先界定哪些操作是可被验证的重复执行，哪些选择承载人物责任。

## 4. 与严格自走棋的差异

| 维度 | 《圣兽之王》 | 酒馆战棋式自走棋 | Faust 当前方向的未决问题 |
|---|---|---|---|
| 人物来源 | 剧情招募，具名且长期存在 | 随机供给，可重复、购买和出售 | 具名学生如何进入阵容而不沦为商店耗材 |
| 玩家主要操作 | 长期培养、编成、条件指令、战场调度 | 购买、出售、刷新、升级、站位和阵容转换 | 手中卡牌与仪式槽如何承担准备阶段 |
| 自动化边界 | 小队接敌后的局部战斗 | 每轮准备后整场战斗 | 哪些过程应自动，哪些人物后果必须人工决定 |
| 替换逻辑 | 可调整小队，但人物通常持续保有 | 高频替换是适应供给和环境的核心 | 人物不可替代性怎样兼容策略调整 |
| 叙事连续性 | 主线、招募人物和世界推进持续存在 | 通常以单局构筑和涌现故事为主 | 关系、成长、伤害和追悔如何回写后续校园行动 |
| 失败反馈 | 战术地图和局部交战共同决定 | 阵容相克、概率和成长速度共同决定 | 玩家能否看懂行动为何成功或失败 |

这张表说明，《圣兽之王》最值得借鉴的是**决策分层与自动执行的可解释接口**，而不是把它的
战斗地图或指令菜单直接移植进 Faust。

## 5. 对当前核心矛盾的启示与反例

Faust 当前最危险的矛盾是：

```text
人物应当长期持续、值得依恋
× 自走棋要求玩家根据供给和局势不断调整
× 项目还必须减少《苏丹的游戏》式管理负担
```

《圣兽之王》给出一种可能答案：**持续的是人物，频繁调整的是人物的编组、位置、装备、条件与
任务**。玩家不一定要出售人物，仍然可以不断重构策略。

但这只是候选假说，不能直接定案。必须主动构造反例：

1. 如果最优玩法要求每场都重写大量条件，自动化会把操作负担转移成规则编程负担。
2. 如果角色拥有强烈剧情身份却能被任意改造成任何功能，人物差异可能只剩皮肤。
3. 如果角色定位过于固定，玩家可能在发现最优编队后长期不再调整，失去自走棋的持续构筑。
4. 如果自动结果缺少可读因果，玩家会把失败归因于系统擅自行动，而不是自己的准备。
5. 如果每位人物都需要独立关系、装备、指令和成长页面，具名化反而可能放大管理过载。

这些反例是后续原型要攻击的问题，不是用更多剧情或数值掩盖的问题。

## 6. 放进“单机剧情叙事自走棋”市场后的正确位置

截至本次检索，市场不是完全空白，而是分成三个相邻层级：

### A. 自动战斗与完整叙事已经成功

- 《圣兽之王》：最强的具名人物、长期培养、完整叙事与自动局部战斗案例；官方销量超过
  100 万。
- 《循环勇者》：单机、故事推进和自动战斗成立，首周销量超过 50 万；但核心是地图构筑与
  单主角循环，不是多人关系阵容。
- 《妖之乡》：故事驱动的单机收集 RPG 与自动战斗成立，官方公布全球销量超过 15 万；但
  核心叙事主体更接近玩家冒险和生物收集。

### B. 单机自走棋已经形成可见的独立游戏市场

《Tales & Tactics》《Teamfight Manager》《The Dungeon Beneath》《Hadean Tactics》、
《Gladiator Guild Manager》等说明单机准备—自动结算循环并非无人购买。但这些作品多以
Roguelite 构筑、经营或可替换单位为核心，持续的人物关系叙事通常较弱。

### C. 严格交叉点仍缺少标杆

《Kilta》直接采用“单机自走棋策略 RPG、成长中的独特角色群和故事”的定位，却只形成小型
市场样本。《Legion Hearts》曾尝试把具名角色牌组、自动结算、非线性角色故事和单机买断制
结合，但没有完成商业发行；其复盘还暴露了规则难解释、受众定位模糊、视觉预期和制作成本问题。

因此当前最稳妥的判断是：

> 严格交叉点是“尚无公认标杆的市场空缺假说”，不是“已经证实存在需求的蓝海”。

## 7. 对 Faust 的直接约束

后续方案引用《圣兽之王》时，至少回答：

1. 玩家在自动执行前具体配置了什么？
2. 自动执行后哪些结果能追溯到这些配置？
3. 同一人物的成长、关系和后果怎样跨手牌、仪式、校园与自动行动持续？
4. 玩家调整的是人物本身、人物的任务，还是人物之间的组织关系？
5. 调整策略是否要求出售、抹除或把具名人物当成一次性素材？
6. 新增的编成和指令是否真正替代旧管理，还是叠加在手牌与仪式负担之上？

只回答“战斗自动播放”“人物很多”或“画面像《圣兽之王》”，均不构成机制方案。

### 9.1 战术系统：优先级 × 行动 × 条件的三层结构

战术菜单分三层，接敌后按此顺序自动判定（[`UO-RULE-002`]）：

```text
优先级（Priority）→ 按序号逐个检查行动；无法满足则下移
行动（Action）→ 主动技能（红色，角色回合激活）或被动技能（蓝色，条件满足即激活）
条件（Condition）→ 每个行动可设条件；条件不满足则跳过该行动
```

关键规则：

- 被动技能有独立于主动技能的优先级列表（[`UO-RULE-002`]）。
- **所有主动技能条件都不满足时，该角色回合被跳过**——条件过严会让角色罚站（[`UO-GUIDE-001`]）。
- 编排经验：条件越严的行动放越上面（两个条件的行动放最顶），并在列表底部留一个无条件行动
  兜底，避免整回合被跳过（[`UO-GUIDE-001`]）。

### 9.2 条件修饰语义：只有“优先”和“仅”两类

玩家实测总结（[`UO-RULE-003`]、[`UO-GUIDE-006`]）：

| 修饰 | 语义 |
| --- | --- |
| 优先 | 必然触发，作为目标选择词（如“优先 HP 最低”） |
| 仅 | 条件满足才触发；不满足则跳过本条，执行下一顺位 |
| 优先 + 仅 | 最常见：条件触发 + 目标选择（如“仅敌 50% HP 以下 + 优先 HP 最低”） |
| 仅 + 仅 | 两条必须同时满足；用于针对特定单位组合 |
| 优先 + 优先 | 判定顺序：1+2 同时满足 > 仅 2 > 仅 1 |
| 【优先前排/优先后排】 | 无论位置，最优先执行 |

额外规则（[`UO-GUIDE-006`]）：

- “第 N 次行动时”类技能判定为“仅”。
- **近战物理技能无法越过前排打后排**——不要给近战物理技能编写后排词条。
- 条件词有语义陷阱：“后排”= 只打后排（无后排则跳过）；“优先后排”= 有后排打后排、无后排
  仍可用。这是 [§9.7](#97-对-faust-的直接数值启示) 可读性启示的直接来源。

### 9.3 技能触发与优先级：对 Faust 最直接的结构参考

条件系统是整个游戏“可解释自动执行”的核心，也是 Faust 条件式自动战斗假说的最直接参照：

- 表达力：目标（HP 最低/重甲/前排/后排/兵种）+ 时机（第 N 次行动/受击时/队友攻击前）+
  条件（仅/优先）可组合出具体战术；
- 冲突处理：优先+优先 的“1+2 > 2 > 1”顺序、被动独立优先级、无条件行动兜底；
- 可诊断性：条件与目标分开显示，失败原因可归因到“条件没满足”还是“目标不存在”；
- 修改成本：每个角色一个战术页，可整体套用战术模板（Tactics Template）快速切换
  （[`UO-GUIDE-001`]）。

这正面回应了原 §3.2 的“条件表达能力/冲突处理/可预见性/诊断能力/修改成本”五个问题中的
表达能力与冲突处理两项；其余三项（开战前可见信息、失败归因、页面步骤）仍缺操作级数据。

### 9.4 伤害与命中公式（玩家实测）

玩家实测公式（[`UO-RULE-004`]、[`UO-RULE-005`]）：

```text
攻击力 =（基础面板攻击 + 武器威力）×（加攻倍率 + 减攻倍率）   # 增减益代数叠加
防御力 =（基础面板防御 + 装备防御）×（加防倍率 + 减防倍率）
总伤害 = [攻击力 − 防御力] ×（技能威力/100）× 兵种特性补正    # 四舍五入；攻击<防御时保底 1
暴击   = 总伤害 ×（150% + 暴击增伤倍率）
格挡   = 减伤 25%（无盾）/ 50%（小盾）/ 75%（大盾）
命中率 =（命中 − 回避）× 技能命中倍率 × 兵种特性补正           # 向下取整
```

兵种特性补正例：骑兵对步兵、弓兵对飞行伤害 ×2；地面近战打飞行命中 ×0.5
（[`UO-GUIDE-006`]）。

异常状态（[`UO-RULE-006`]）：燃烧 20 HP/层、中毒下次行动损失最大 HP 30%、冰冻无法行动
（受击解除、回避变 0）、黑暗下次攻击命中必为 0（必中不可抵消）、昏厥跳过一回合。

### 9.5 职业、转职与编队数值

- 职业约 **60 种**（基础+进阶）；角色**不能横向换职**，只能沿固定基础→进阶路径转职
  （如 Lord→High Lord、Wizard→Warlock）（[`UO-RULE-007`]、[`UO-GUIDE-004`]）。
- 转职解锁：声望等级 **B**（累计 **1750** 声望点），在任何已解放堡垒进行；消耗荣誉
  **25（基础职业）—50（独特职业）**；转职立即增加 AP/PP 并解锁新技能（[`UO-RULE-008`]）。
- 小队最大 **5 人**（满扩容）；扩容与解锁新单位槽都消耗荣誉，并有声望等级门槛
  （[`UO-RULE-008`]、[`UO-GUIDE-002`]）。
- Valor 系统：每场战斗上限 **10 点**；部署新单位、使用 Valor 技能（战斗外/战场技能）消耗
  Valor；击败敌人、解放城镇/堡垒恢复（[`UO-RULE-009`]、[`UO-GUIDE-005`]）。
- 成长类型：HP 型 / 力量型 / 防御型决定属性成长方向；同名职业同成长类型属性上限一致
  （[`UO-RULE-010`]、[`UO-GUIDE-006`]）。

### 9.6 管理负担的量化线索

- 70+ 可招募角色、约 60 种职业、小队 5 人、每角色独立战术页 + 被动独立优先级
  ——理论上限是**数十个角色 × 每人多条主动/被动条件**（[`UO-GUIDE-007`]）。
- 游戏提供 Tactics Template（战术模板）整体套用/切换，以及按角色套用预设，缓解逐条配置成本
  （[`UO-GUIDE-001`]）。

### 9.7 对 Faust 的直接数值启示

1. **条件系统是“可解释自动化”的教科书**：条件与目标分开、只有“优先/仅”两种修饰、
   无条件兜底行动——这套语法让玩家能在开战前读懂“我的角色会做什么、为什么”。
   Faust 若做条件式自动战斗，应优先检验这套语法的可读性，而不是更复杂的规则引擎。
2. **人物不可替换，但配置可重构**：职业固定、人物不可横向换职，调整空间在编队位置、
   装备、技能条件与小队组合。这正是 Faust“不卖人物、只重构关系/任务”假说的现成参照
   （呼应原 §5 第 2 条反例）。
3. **“优先/仅”语义差异是认知负担来源**：“后排”与“优先后排”一字之差改变整个行为，
   条件放错位置会让技能永远不触发。Faust 若引入同类条件词，必须决定如何向玩家展示语义
   差异（§9.2 表格是现成的教学材料）。
4. **数值门槛是可读的进度目标**：声望 B = 1750 点、转职 25—50 荣誉、小队 5 人、Valor 10 点
   ——所有长期目标都有明确数值。Faust 的跨局成长若采用类似结构，应保持“每个长期目标
   都有玩家可读的数值门槛”。
5. **本节边界**：以上全部为攻略级社区来源（B 级），未经官方确认；伤害公式为 demo 版本
   玩家实测，可能与正式版有出入。任何数值不得直接抄入 Faust 原型，只作为结构参考。
