## 0. 先读结论

公开资料已经足够支持我们进入定量原型阶段，但还不足以直接给出 Faust 的规则答案。

1. **《苏丹的游戏》已经能够被静态解析。** 事件/仪式配置、槽位、条件、结算分支和结局条件可以转成图；官方也公开过部分事件选择的聚合数据。但是没有逐玩家运行轨迹，因此无法回答手牌从多少张开始失控、玩家找牌需要多久、一次仪式实际比较了多少候选人，以及失败来自决策还是界面摩擦。
2. **《风花雪月》和 P5R 已经能够被表示为有限日程优化问题。** 招募阈值、成长路线、人物可用日、关系点、期限和逐日全目标攻略都较完整。这些资料能够证明规则如何连接、目标是否存在联合可行解，却不能证明校园玩法是吸引系列新玩家的单一原因。
3. **《酒馆战棋》拥有最成熟的公开定量生态。** 它同时具有战斗模拟、小时级聚合统计、官方技能分段、版本化静态数据和学术搜索代理。这套生态最值得借鉴的不是某项平衡结论，而是把“规则状态—玩家选择—自动结算—概率反馈—分层遥测”连成闭环的方法。
4. **四川麻将已经有状态压缩、向听/缺牌数、胜率和期望局数模型。** 但没有找到专门研究血流成河“首次和牌后继续摸打和反复结算”的节奏数据。我们与《酒馆战棋》的类比仍是有结构依据的假说，必须自行建模。
5. **认知负荷、人物依恋和叙事选择已有成熟测量工具。** NASA-TLX、检测反应任务、视觉搜索指标、选择意义、角色认同、悲伤与永久死亡研究都可借用；它们不能替代在 Faust 原型上测量真实玩家。

贯穿全部资料的共同缺口是：

> 公开资料擅长描述规则空间、构造可行解和统计既有行为，却没有替我们验证“怎样在保留人物后果的同时减少管理负担”。

因此，下一阶段不应继续以文章数量代替研究进度，而应制作一个可记录决策面、操作轨迹、人物后果和主观体验的最小原型。

## 1. 研究问题

本轮资料检索不是为了回答“哪些游戏好”，而是为了回答五组可用于设计的具体问题。

### 1.1 《苏丹的游戏》的负担能否被定量定位

- 静态内容规模有多大？
- 单个仪式的槽位、条件和结算分支能否转成图？
- 官方是否公开了逐玩家手牌、操作和决策时间？
- 玩家抱怨的卡牌管理问题是否获得制作组确认？
- “后期负担”究竟是状态很多，还是当前决策面没有被压缩？

### 1.2 校园日程为什么能把人物养成与战斗连接起来

- 《风花雪月》的招募、关系、成长和战斗资源如何相互换算？
- P5R 的日期、人物可用性、关系点和迷宫期限能否形成可计算的日程模型？
- 全目标攻略究竟证明了什么？
- 商业成绩和高周目调查能否证明校园玩法造成破圈？

### 1.3 《酒馆战棋》怎样建立定量闭环

- 自动战斗如何从演出变成概率模拟？
- 英雄、阵容和推荐为什么必须按玩家熟练度分层？
- 准备阶段能否用搜索算法建模？
- 哪些数据是公开的，哪些只是商业服务的聚合结果？

### 1.4 麻将与血流成河能提供什么底层模型

- “距离成型”怎样计算？
- 随机供给中仍可获得的对象为什么必须进入模型？
- 首次成型后继续运转需要哪些状态变量？
- “更爽”能否从规则类比直接推出？

### 1.5 如何验证认知负荷和人物意义

- 怎样同时测量主观负担、客观表现和真实操作？
- 怎样区分人物认同、乐趣、能力感和选择意义？
- 永久死亡为什么有时产生意义、有时只产生挫败？
- 自动化是否真的释放了注意力，而不是让玩家失去理解与责任？

## 2. 检索和证据处理方法

### 2.1 来源优先级

本研究按下列顺序使用证据：

1. 官方规则、官方遥测、官方财报和开发者数据说明；
2. 同行评审论文、学位论文及作者公开全文；
3. 可检查代码或数据结构的开源工具；
4. 机制数据库、完整攻略和社区计算表；
5. 玩家评价与媒体评论，只用于发现问题和建立主题，不用于估计总体发生率。

《苏丹的游戏》的本地逆向资料另按项目规定分层：反编译方法体用于行为事实，`dump.cs` 用于结构和签名，原始 JSON 用于配置事实。本文只做静态规模盘点，不把“配置存在”写成“运行时一定出现”。

### 2.2 纳入标准

一项资料至少满足以下一项才进入正文：

- 给出可复查的样本量、变量、规则表或计算过程；
- 能导出结构化配置或事件图；
- 提供可以复用于本项目的实验方法；
- 明确公开证据的边界，能阻止错误推断；
- 能把此前的定性判断转成可证伪假说。

没有来源的数值转载、无法解释样本的数据面板、营销式“AI 分析”和个别评论中的夸张数字不进入计算。

### 2.3 四种证据必须分开

| 证据层 | 回答的问题 | 典型材料 | 不能越界推断的内容 |
|---|---|---|---|
| 规则/配置 | 系统允许什么 | JSON、规则表、日历、卡牌 API | 玩家实际看见或选择了什么 |
| 构造/模拟 | 在假设下会发生什么 | 全目标攻略、蒙特卡洛、MCTS、马尔可夫链 | 普通玩家是否理解、喜欢或采用该方案 |
| 行为数据 | 玩家实际做了什么 | 选择率、对局日志、调查、评分分段 | 行为背后的心理原因和单一因果关系 |
| 体验实验 | 玩家如何感受任务 | TLX、DRT、眼动、访谈、量表 | 长期留存、商业结果和完整游戏体验 |

这一区分是整份报告的核心。静态事件树不能证明玩家走过该路径；聚合选择率不能重建一名玩家的思考过程；主观负担也不能替代完成时间和错误率。

### 2.4 推理标记

后续智能体使用本文时，应把内容分成四类：

- **来源事实**：资料直接公开的规则、数字或方法；
- **本报告计算**：根据公开数字进行的算术、形式化或图模型转换；
- **设计解释**：与现有事实相容、但尚未被因果验证的解释；
- **待验证假说**：必须通过 Faust 原型或新数据才能决定的命题。

若 `-Check` 报告快照过期，先无参数运行脚本生成新快照，再审查语料指纹、计数和本文结论是否需要更新。不得只改本文中的数字。

## 3. 《苏丹的游戏》：静态内容已经可计算，运行负担仍是空白

### 3.1 已公开的配置提取能力

[事件/仪式查看器](https://github.com/AC-HUB-AC/Sultan_s_Game_Event_Viewer)读取游戏 `StreamingAssets/config/rite` 目录，可以展示事件分支、卡槽信息和不同结算。其仓库说明：内置快照对应 2025 年 4 月 1 日前的 2022.3.58 版本，共 1153 个事件；用户也可以选择新版游戏的本地配置目录。

[结局查看器](https://github.com/AC-HUB-AC/Sultan_s_Game_Ending_Viewer)采用相同思路读取 `StreamingAssets/config/after_story`，展示结局条件和分支。

这两项工具证明了三件事：

1. 仪式和结局的主要作者空间可以从配置中提取；
2. 槽位条件、结算条件和后续动作可以转成结构化数据；
3. 事件与结局适合用图论和静态可达性方法研究。

它们没有证明：

- 1153 个配置会在同一局出现；
- 某个配置一定能在当前版本到达；
- 玩家实际看过、理解或选择过某个分支；
- 配置数量等于玩家同时管理的状态数量。

### 3.2 本地当前语料的静态盘点

为避免把公开工具的旧版数字当成当前配置规模，本报告对只读逆向语料做了独立文件计数和 JSON 字段统计。2026-08-13 的本地快照包含：

| 静态对象 | 数量 | 解释 |
|---|---:|---|
| `config/rite/*.json` | 1495 | 仪式定义文件，不是开局可见仪式 |
| `config/after_story/*.json` | 66 | 结局主体配置文件，不等于 66 个玩家可见结局 |
| `round_number == 0` 的仪式定义 | 122 | 静态时长字段为 0；是否生成和开放仍需运行链证明 |
| `round_number >= 1` 的仪式定义 | 1373 | 跨日至少一轮的静态定义 |
| `auto_begin == 1` | 404 | 自动开始标记，不等于自动结算 |
| `auto_result == 1` | 18 | 自动结果标记，仍不能单独推出运行时触发 |
| `cards_slot` 中的槽位定义总数 | 5393 | 1494 个仪式含至少一个槽位，单仪式最多 17 个 |
| 三类 settlement 数组中的分支项 | 8994 | 1491 个仪式含结算分支，单仪式最多 334 项 |

计数方法是逐个解析当前 JSON，再对顶层字段和数组长度汇总。它比文件名猜测可靠，但仍属于**配置事实**。特别是同名仪式变体、生成条件、开放条件、事件动作和运行队列会决定玩家实际遇到的子集。

`after_story` 中一项 `extra` 是一个条件—文本条目，不应直接被叫作“一个结局”；同一主体下可能有大量互斥或重叠条件。结局树需要先解析条件，再结合运行状态和优先级判断可达性。

### 3.3 怎样建立事件树和结局树

事件图至少需要下列节点与边：

| 图元素 | 配置来源 | 含义 |
|---|---|---|
| 仪式节点 | rite ID | 一个静态仪式定义 |
| 槽位节点 | `cards_slot` | 玩家可投入对象的位置与条件 |
| 结算分支 | `settlement_prior`、`settlement`、`settlement_extre` | 条件成立后的结果集合 |
| 状态条件 | `condition`、`open_conditions` | 进入或选择分支所需状态 |
| 生成边 | `action.rite`、事件或 loot 结果 | 一个状态如何创建后续定义的实例 |
| 状态写入边 | result、counter、tag、card 操作 | 当前结算怎样改变后续可达性 |
| 结局节点 | `after_story` 条件—文本条目 | 最终状态如何映射到结局输出 |

可计算指标包括：

- 节点入度和出度；
- 每个仪式的槽位数、分支数和条件数；
- 从已验证起点到内容节点的最短路径；
- 互斥条件、汇合点和瓶颈；
- 静态不可达或缺少生成入口的配置；
- 不同人物状态影响多少后续节点；
- 一条结局路线需要同时维护多少前置状态。

但是，静态图必须与运行时生成链分开。正确的状态顺序是：

```text
配置定义
→ 某个事件/loot/卡牌动作创建运行实例
→ 开放条件满足
→ 玩家看见并投入卡牌
→ 仪式开始
→ 到达结算时机
→ 选择或命中具体结算分支
→ 状态回写与后续生成
```

仅凭 JSON 中存在一条边，不能证明玩家路径中一定发生这条转移。

### 3.4 官方聚合选择数据做到了什么

制作组发布过[《苏丹的游戏》官方数据总结](https://store.steampowered.com/news/app/3117820/view/543363919951963515)。公开说明将数据限定为启用数据收集玩家的事件选择，并以聚合形式展示，不把数据关联到具体玩家。主要结果以信息图呈现，没有提供逐玩家、逐局、逐日的结构化原始数据。

它能够回答：

- 某些被统计事件中，哪项选择更常见；
- 少数路线或角色选择是否在总体上极端偏斜；
- Faust 若复现同构选择，自己的聚合分布是否明显不同。

它不能回答：

- 选择发生时玩家有多少张牌和多少个仪式；
- 玩家查看了哪些候选对象；
- 从打开仪式到确认花了多久；
- 同一玩家此前经历了什么；
- 玩家为什么选择、读档、退出或错过期限；
- 新手与熟练玩家是否采用不同策略。

这类数据是**横截面的聚合选择**，不是**纵向的玩家路径**。

### 3.5 卡牌管理痛点已经得到什么程度的确认

[1.0.11241 更新说明](https://steamdb.info/patchnotes/17924707/)中，制作组明确称卡牌管理问题被频繁反馈，并预告自动筛选分类功能，还表示考虑为特殊后续事件增加视觉提示。

这足以支持以下存在性判断：

> 卡牌整理和后续事件可见性不是研究者凭空想象的问题，制作组确实收到过重复反馈并采取产品行动。

但公告没有公开：

- 每日平均卡牌数；
- 卡牌数量的分布和周目变化；
- 找到目标卡所需时间；
- 每个槽位的候选卡数量；
- 玩家遗漏期限的原因；
- 自动分类上线前后的完成时间、错误率或留存变化。

因此，外部资料支持“痛点存在”，不支持“负担从某个固定手牌上限开始”。

### 3.6 把后期负担转成可测变量

“手牌太多”至少应拆成四类不同变量。

#### 状态规模

- `H_t`：决策时刻的手牌对象数；
- `R_t`：当前可见仪式数；
- `D_t`：具有期限或需要持续监控的对象数；
- `S_t`：当前人物、装备、关系和标签中的有效状态数。

#### 决策面规模

- `E_{r,s,t}`：时刻 `t` 中，仪式 `r` 的槽位 `s` 可用卡数量；
- `C_{r,t}`：仪式可形成的合法组合数量；
- `A_t`：玩家此刻真正不同的高层行动方案数；
- 候选方案的相似度：大量机械等价方案不应被当作大量有意义选择。

#### 界面和操作成本

- 从打开仪式到首次悬停目标卡的时间；
- 查看卡牌详情次数；
- 跨分区切换、拖拽、取消和重放次数；
- 执行一个已经解决过的日常任务所需点击数；
- 错误投放和回退率。

#### 结果和体验

- 任务完成率、期限遗漏率和读档率；
- 玩家能否解释失败原因；
- NASA-TLX 六维负担；
- 玩家认为决策困难来自取舍、信息寻找还是规则不透明。

### 3.7 《苏丹的游戏》阶段结论

**来源事实：** 静态作者空间已经可以大规模提取；官方有聚合选择数据；制作组确认卡牌管理被频繁反馈。

**本报告计算：** 当前本地配置快照包含 1495 个仪式定义、5393 个槽位定义和 8994 个结算分支项，说明作者空间庞大且高度分支化，但这些数字不等于单局决策负担。

**设计解释：** 后期问题更可能是“有意义状态增长超过界面的压缩、检索、优先级和自动化能力”，而不只是策略深度过高。

**待验证假说：** 当手牌和仪式增长时，玩家时间主要消耗在寻找合法对象和重复执行，而不是比较真正不同的人物后果。

## 4. 《风花雪月》：规则和结果数据充分，破圈因果证据不足

### 4.1 招募系统提供了可计算的资源替代关系

[Triangle Attack 招募表](https://www.fe3h.com/recruitment)列出人物在 None、C、C+、B、B+ 支援状态下的属性和技能门槛。页面给出的通则是：每经过一个支援阶段，属性要求按原始值降低 20%；技能等级也按离散表下降。A 支援时学生可忽略主角属性与技能门槛加入，B 支援后每周还有 10% 概率主动申请加入。

例如原始属性门槛为 20 时，公开表为：

| 支援阶段 | 所需属性 |
|---|---:|
| None | 20 |
| C | 16 |
| C+ | 12 |
| B | 8 |
| B+ | 4 |

这意味着玩家至少拥有两条可替代的投资路径：

```text
练主角属性/技能
→ 直接达到招募阈值

投入聚餐、礼物、协助等关系行动
→ 提高支援
→ 降低属性/技能阈值或等待主动加入
```

因此，关系不是战斗外的纯文本奖励，而是能改变招募成本的数值变量。

### 4.2 成长计算表提供了静态期望模型

[《风花雪月》队伍与职业成长计算表](https://docs.google.com/spreadsheets/d/1wKoJPzmTwp7WwMgMTTd_Io_kB29LwEkWGiov80mIbNg/edit)允许选择人物、等级和职业路线，并估算期望属性、职业技能要求和熟练倾向。表格说明主要原始资料来自 Serenes Forest，并假设达到最低等级后立即转职。

可以把其方法概括为：

```text
期望属性
= 初始属性
+ 各等级区间的人物成长率期望
+ 各职业阶段的成长修正
+ 职业基础值或固定修正
```

它适合比较培养路线的平均结果，不适合证明单局可靠性，因为：

- 随机成长存在方差；
- 高等级招募人物的内部成长处理不完全清楚；
- 作者标注部分特殊角色估算不准确；
- 期望值不能表示最差情况和达到职业门槛的概率。

### 4.3 玩家调查说明高参与样本存在大量重复游玩

《Fami通》在 2019 年 9 月 27—30 日调查 3492 名玩家；[英文整理](https://www.frontlinejp.net/2019/10/18/fire-emblem-three-houses-player-survey-results/)注明并非每人回答全部问题。周目题共记录 3475 个回答：

| 所处周目 | 人数 | 占该题回答者 |
|---|---:|---:|
| 第一周目 | 418 | 12.0% |
| 第二周目 | 1081 | 31.1% |
| 第三周目 | 827 | 23.8% |
| 第四或更多 | 1149 | 33.1% |

这是本报告根据公开人数重新计算的比例。它说明主动参与调查的玩家中，多周目极其常见；不能推断全部购买者有相同比例，因为 Fami通读者、愿意作答者和发售初期仍高度参与的玩家存在明显自选择。

调查还记录了学级、难度、人物偏好和联网功能使用，适合把“路线选择—角色偏好—熟练度”放在同一份问卷中，却没有记录修道院行动日志，也没有“是否首次接触火纹”的可靠因果分组。

### 4.4 商业数据证明市场结果，不证明单一机制原因

[任天堂 2019 财年第二季度经营方针资料](https://www.nintendo.co.jp/ir/pdf/2019/191101_2e.pdf)显示，《风花雪月》上市 13 周实销超过 170 万，是当时系列最佳开局；北美占总实销超过 50%。

这能证明：

- 市场触达确实扩大；
- 海外市场对结果非常重要；
- “《风花雪月》成功破圈”不是只靠口碑印象的说法。

它不能排除：

- Switch 装机量和平台生命周期；
- 《觉醒》《英雄》等前作积累；
- 宣发、视觉、角色设计和发售窗口；
- 多路线和社交传播；
- 校园结构之外的其他变化。

所以销量不能单独证明“修道院玩法造成增长”。

### 4.5 开发者访谈提供的是机制意图和制作过程

[RPG Site 开发者访谈](https://www.rpgsite.net/interview/8711-fire-emblem-three-houses-interview-intelligent-systems-nintendo-talk-bringing-the-beloved-strategy-rpg-series-to-switch)中，草木原俊行说明：旧作人物陆续加入，玩家了解他们的时间不均；《风花雪月》让人物从开局就在学院中出现，使玩家能够更均衡地认识他们并建立更深关系。他也说明修道院 RPG 部分经历了大量试玩、讨论和平衡调整。

这支持以下机制链：

```text
固定共同体从开局存在
→ 重复相处和定向培养
→ 玩家对具体学生形成责任
→ 同一人物进入战斗并承担风险
→ 战斗结果回到成长与关系
```

但访谈仍是设计意图，不是随机对照实验。它不能告诉我们多少新玩家因校园玩法购买或留存。

### 4.6 怎样把校园循环转成模型

可以把一个月表示为有限资源分配问题：

- `T`：可用周末和工作日时段；
- `P_t`：第 `t` 周可用探索/战斗/指导点；
- `M_{i,t}`：学生 `i` 的动机；
- `K_{i,k,t}`：学生 `i` 在技能 `k` 上的等级；
- `B_{i,j,t}`：人物关系或支援进度；
- `Q_m`：月底任务对队伍的能力要求；
- `X_{a,t}`：是否在时段 `t` 执行动作 `a`。

约束包括：

- 每个时段最多选择允许的行动；
- 指导消耗动机和指导名额；
- 聚餐、礼物等既影响关系也恢复动机；
- 职业考试需要技能和等级门槛；
- 战斗提供经验与关系，但消耗休息日资源；
- 月底任务是培养结果的周期性验收。

模型输出不只应是“最高战力”，还应包括：

- 有多少学生得到有效培养；
- 关系投资是否改变招募或战斗方案；
- 为保护某个人物牺牲了哪些其他机会；
- 战斗结果是否改变下一月的可用选择。

### 4.7 《风花雪月》阶段结论

**来源事实：** 招募阈值、支援折扣、成长路线、玩家调查和销量均有公开数字；开发者明确说明固定学院共同体和大量修道院试玩。

**本报告计算：** Fami通周目题回答者中约 88% 已进入第二周目或以上，但该比例只描述高参与自选择样本。

**设计解释：** 《风花雪月》降低的可能不是战棋规则本身的难度，而是玩家“为什么愿意关心并学习战棋”的动机门槛。校园生活先建立责任，战斗再检验培养。

**待验证假说：** 若移除“同一具名人物跨日程、培养和战斗持续存在并承担后果”的闭环，只保留大量校园活动，吸引力和人物责任感会明显下降。

## 5. P5R：完整日程能证明有解，不能证明玩家感到自由

### 5.1 日历数据库已经接近约束表

[P5R 完整日历数据库](https://megatenwiki.com/wiki/Calendar_in_Persona_5_Royal)按日期列出天气、昼夜自由时段、固定事件、协助人可用性、解锁、前置、自动升级和关系上限。它允许把游戏表示为离散时间的约束满足问题。

基本变量可以定义为：

- `t`：具体日期的白天或夜晚时段；
- `x_{a,t}`：时段 `t` 是否选择行动 `a`；
- `r_{i,t}`：协助人 `i` 在 `t` 时的等级；
- `p_{i,t}`：与协助人 `i` 的隐藏关系点；
- `g_{k,t}`：社会属性 `k` 的等级或点数；
- `d_j`：迷宫、委托或特殊事件的期限；
- `v_{i,t}`：人物 `i` 在该时段是否可用。

典型约束是：

```text
每个自由时段最多执行一个主要行动
人物不可用时 x = 0
未达到社会属性/委托/剧情前置时不可升级
关系点达到阈值后下一次互动才能升阶
迷宫必须在期限前完成
部分迷宫和委托可以批处理，以减少占用日期
```

### 5.2 全目标攻略是构造性可行证明

[All Confidant Events 路线](https://gamefaqs.gamespot.com/ps4/260936/persona-5-royal/faqs/78212/ace-how-to-use)记录最优对话、预期关系点、相同 Arcana 的额外 `+1`、迷宫批处理、委托和存档安排。多份逐日 100% 路线证明：在攻略的前提和执行精度下，至少存在一条能够联合完成大量目标的日程。

在数学上，这相当于给出一个可行向量 `x`，满足既定约束：

```text
找到一条完整路线
⇒ 问题至少有一个可行解
```

它不等于：

```text
找到一条完整路线
⇒ 这是唯一解或最优解
⇒ 普通玩家能发现它
⇒ 玩家不会依赖攻略
⇒ 玩家主观上感到自由
```

### 5.3 可以继续计算什么

在日历和完整路线基础上，可以计算：

- **关键路径**：哪些人物或事件一旦延误就无法补救；
- **松弛时间**：某项目标最晚可推迟多少时段；
- **批处理收益**：把多少委托集中进一次迷宫可节省多少日期；
- **恢复空间**：偏离攻略一次后还有多少替代日；
- **可选度**：同一状态下有多少行动能够保持全目标可行；
- **攻略脆弱度**：天气、随机点数或错误回答改变时，路线失败概率多大。

没有逐玩家遥测时，仍然无法知道普通玩家实际怎样分配时间、何时查攻略、在哪些条件上误判。

### 5.4 P5R 阶段结论

**来源事实：** 日期、可用性、关系点机制和逐日完整路线高度结构化。

**本报告计算：** 可将完整攻略视为约束满足问题的构造性可行解，并进一步计算关键路径、松弛和恢复空间。

**设计解释：** P5R 的轻松感不来自目标很少，而来自任一时刻的选择被日历、地点和人物可用性压缩到有限集合。

**待验证假说：** Faust 也可以保留庞大的世界状态，但必须把每个决策窗口压缩为少量当前可行动对象；否则静态内容规模会直接变成界面搜索负担。

## 6. 《酒馆战棋》：最完整的“状态—选择—自动结算—反馈”定量生态

### 6.1 Bob's Buddy 把自动战斗变成概率分布

[HSReplay 的 Bob's Buddy 说明](https://hsreplay.net/battlegrounds/overlay/)称，工具在战斗开始时读取公开日志中的场面，并模拟超过 10000 次随机战斗，给出胜、负、平、致死和淘汰概率。其环境统计每小时更新，新补丁通常在两小时内出现数据。

给定固定场面 `s`，一次模拟得到结果 `Y_i`，例如胜利记为 1、否则为 0，则：

```text
p_hat(win | s) = (Σ Y_i) / N
```

若把模拟视为独立伯努利试验，`N = 10000` 时，蒙特卡洛抽样标准误在 `p = 0.5` 附近最大：

```text
SE ≈ sqrt(p(1-p)/N) = sqrt(0.25/10000) = 0.005
```

也就是约 0.5 个百分点。这个数只描述重复采样误差，不包含模拟器规则错误、日志缺失和未知信息造成的模型误差。

它对 Faust 的意义是：自动结算不必只输出一次“赢/输”，还可以在调试或解释层提供：

- 当前配置的结果分布；
- 哪个人物或关系是胜负关键；
- 替换某一人后的反事实变化；
- 当前失败是高概率结构问题还是低概率波动。

### 6.2 小时级聚合统计解决版本变化，但数据并非完全开放

HSReplay 的价值不仅是单场模拟，还在于把大量对局聚合为英雄、阵容、种族和房间环境统计，并快速响应补丁。部分深度数据属于 Tier7 服务，原始逐局数据并未全部开放，因此外部研究者不能独立复算所有榜单。

这形成两种互补证据：

- 规则模拟器回答“给定状态的随机结果”；
- 真实聚合对局回答“玩家实际把哪些状态带进了战斗，以及最终表现如何”。

二者不能互相替代。高胜率场面可能极难形成；常见阵容也可能只是容易理解而非理论最强。

### 6.3 官方分段数据证明平衡结论依赖熟练度

[暴雪设计师数据说明](https://www.bluetracker.gg/hearthstone/topic/us-en/87311-developer-insights-battlegrounds-balance/)公开了一个伙伴版本的活跃玩家分段：活跃定义为过去 20 天至少玩 5 局；前 50% 为 5700 MMR、前 25% 为 6500、前 10% 为 7000、前 1% 为 8300。全体玩家与前 1% 玩家的前十英雄名单差异明显。

设计师给出的解释是：方向明确、围绕单一种族的英雄更容易让多数玩家成功，而高手能够利用更复杂的经济和组合线。

这支持一条对 Faust 很重要的方法原则：

> 推荐、自动化和难度不能只看总体平均，也不能用高手数据代表所有玩家。

至少应按以下变量分层：

- 是否第一次接触此类卡牌/日程系统；
- 已完成的局数或章节数；
- 是否使用提示或攻略；
- 是否能正确解释槽位与人物关系；
- 对自动推荐的接受度；
- 实际表现和估计不确定性。

### 6.4 评分系统提醒我们保存“不确定性”

[暴雪关于个人评分的数据科学说明](https://news.blizzard.com/en-gb/article/23239989/developer-insights-personal-rating-in-hearthstone-battlegrounds)解释，系统不只维护一个技能估计，还维护该估计的不确定性；新玩家数据少，因此方差更高。文章以公测早期分布和八人对局的 56 组两两比较解释更新逻辑。

对 Faust 来说，玩家熟练度不应被简单记录成一个固定标签。第一次测试中操作慢，可能来自不熟悉；多次测试后仍慢，才更可能是稳定的界面或规则问题。任何自动推荐效果都应同时报告样本量和置信区间。

### 6.5 结构化静态卡池支持版本研究

[HS BG Cards API](https://hsbg.cards/api-docs)提供当前、历史和即将上线卡牌的属性、等级、文本、关联卡和补丁状态。它可以用于计算：

- 卡池规模与等级分布；
- 关键词和永久成长文本的频率；
- 每次补丁的增删改幅度；
- 某类成长引擎出现和退出环境的时间；
- 静态卡池变化与聚合表现变化的对应关系。

静态卡牌数据仍不能证明玩家选择率和真实表现。它承担的是版本化规则输入，不是行为输出。

### 6.6 MCTS 论文展示完整技术路线，也展示小样本风险

2022 年论文 [Hearthstone Battleground: An AI Assistant with Monte Carlo Tree Search](https://easychair.org/publications/download/Kftf)为 20.0.2 版本建立了购买、出售、打出、刷新、冻结、升级、站位和战斗模拟，并使用 MCTS 搜索准备阶段动作。

这类模型把一轮写成：

```text
当前状态 s_t
→ 枚举合法动作 A(s_t)
→ 选择/扩展动作节点
→ 模拟后续招募和战斗
→ 用胜率、伤害或名次回传价值
→ 推荐动作序列
```

论文最有价值的经验是：

- 必须先有足够准确的规则模拟器；
- 准备阶段的动作组合会指数增长，需要剪枝；
- 战斗随机性需要重复采样；
- 评价不能只有一次胜负，应同时考虑伤害等指标。

但其评价只有一名高手 Dogdog 的 3 组获胜录像、每组 6 回合，共涉及 42 个场上随从和 22 个酒馆随从；模型也只到早期回合。论文报告的优势不能泛化为真实完整对局或其他版本。

### 6.7 跨游戏长期研究提醒我们区分系统激励与稳定偏好

CHI 2026 论文 [Change is Hard](https://arxiv.org/abs/2603.16136)跟踪同一生态中的 4830 名玩家：每人两款游戏均至少有 50 场排位记录，主动采集期为 2023-05-22 至 2024-07-22。研究比较鼓励专精的《英雄联盟》和鼓励随随机供给调整的《云顶之弈》。它提示：玩家即使进入激励不同的系统，也可能保留稳定的专精或转型倾向。

对 Faust 的意义是：如果某些玩家总是保护固定人物、拒绝转型，不能马上判定系统没有提供替代方案；需要同时观察规则给出的机会和玩家跨局稳定偏好。

### 6.8 为什么这是最值得借鉴的定量生态

《酒馆战棋》的生态覆盖了五个层级：

```text
版本化静态数据
→ 精确规则模拟
→ 单状态蒙特卡洛结果
→ 大规模真实对局聚合
→ 按熟练度和版本解释差异
```

相比之下，《苏丹的游戏》目前公开资料主要停留在第一层和少量聚合选择；《风花雪月》与 P5R 主要有第一层和构造性路线；麻将有强数学模型但缺少我们关心的具体规则数据。

### 6.9 《酒馆战棋》阶段结论

**来源事实：** 有超过一万次的单场模拟、小时级聚合数据、官方熟练度分段、版本化卡池和 MCTS 研究。

**本报告计算：** 一万次独立伯努利模拟在最坏情形的抽样标准误约 0.5 个百分点，但这不包含模型误差。

**设计解释：** 自动战斗真正有研究价值的地方，是把复杂结果变成可重复模拟和可观察反馈，而不只是替玩家操作。

**待验证假说：** Faust 若把人物配置后的行动自动化，并提供可理解的因果反馈，可以减少微观执行而保留人物责任；但不同熟练度玩家需要不同强度的提示和自动化。

## 7. 四川麻将与血流成河：已有状态数学，缺少持续结算节奏研究

### 7.1 四川麻将已经有胜率与期望局数模型

2024 年 TU Delft 硕士论文 [Measuring the Game State of Sichuan Mahjong](https://repository.tudelft.nl/record/uuid%3A45412144-6b33-4f18-913c-2a4c4845ec00)针对四川麻将规则产生的双人残局建立马尔可夫链和组合状态度量，计算胜率与期望剩余回合数，并比较进攻型与保守型策略。

马尔可夫模型的基本形式是：

```text
P(s_{t+1} | s_t, a_t)
```

当胜负状态是吸收状态时，可以计算：

- 从当前手牌状态最终获胜的概率；
- 到吸收状态的期望回合数；
- 不同出牌策略如何改变结果；
- 理论计算与模拟结果的偏差。

论文聚焦四川麻将的双人情形，并不等于血流成河四人、多次和牌和反复支付的完整模型。

### 7.2 缺牌数研究说明“距离成型”必须考虑供给

论文 [A Fast Algorithm for Computing the Deficiency Number of a Mahjong Hand](https://arxiv.org/abs/2108.06832)计算手牌完成牌型至少需要多少次换牌，并让算法尊重已知的剩余可用牌。作者报告新算法通常比基线快约 100 倍。

对本项目最重要的不是速度本身，而是：

> 两个静态形状相同的方案，如果可获得的剩余对象不同，它们距离成型的真实价值也不同。

因此，Faust 的“人物/关系组合缺口”不能只按当前已有标签计算，还要考虑：

- 后续环境是否还会提供需要的人物或机会；
- 该对象是否已被其他路线占用；
- 截止日前还剩多少次输入；
- 为等待目标对象需要放弃多少即时收益。

### 7.3 血流成河真正缺少的数据

本轮没有找到专门研究下列问题的公开数据：

- 首次和牌发生在平均第几巡；
- 首次和牌后平均还能再次和牌多少次；
- 两次结算之间的间隔；
- 首次成型速度与最终收益的关系；
- 成型后继续出牌带来的点炮风险；
- 玩家为何认为反复和牌更爽，以及这种偏好如何受水平影响。

现有四川麻将数学研究不能自动填补这些空白。

### 7.4 “血流成河—酒馆战棋”类比的可计算表达

两者共享的不是相同数值成长，而是：

```text
首次形成有效结构
≠ 立即结束

首次形成有效结构
= 启动一个继续接受随机输入并反复反馈的引擎
```

可以为血流成河式结构定义：

- `T_form`：首次成型时间；
- `N_settle`：成型后结算次数；
- `ΔT_settle`：相邻结算间隔；
- `G_post`：成型后的累计收益；
- `R_post`：成型后继续参与导致的风险暴露；
- `V(s)`：当前成型结构在剩余牌流中的期望价值。

在《酒馆战棋》中，对应量不是再次和牌，而是核心阵容形成后的永久成长率、经济增长、每轮战斗结果和淘汰风险。

### 7.5 Faust 必须自行建立的最小模型

如果要检验“首次成型后持续运转”是否适合 Faust，至少需要：

1. 明确什么对象构成可持续结构：人物队伍、关系网络、观念组合或其他状态；
2. 定义首次成型条件，而不是事后凭感觉判断；
3. 定义后续进入的随机输入；
4. 定义每轮产生的成长、收益和风险；
5. 比较一次性结算与持续结算的反馈密度、理解度和策略空间；
6. 记录玩家是否能预期该引擎如何继续工作。

### 7.6 麻将阶段结论

**来源事实：** 已有四川麻将马尔可夫链、胜率、期望局数和通用缺牌数算法。

**本报告计算：** 可以把首次成型后的状态价值拆成成型时间、重复结算次数、间隔、收益和风险。

**设计解释：** 《酒馆战棋》与血流成河相似之处，是有效结构成型后继续接受输入并反复反馈，而不是二者拥有相同成长规则。

**待验证假说：** Faust 若让一套人物/关系结构在首次成型后持续接受事件并产生成长与风险，可能比“一次配方、一次结算、全部归位”形成更连续的养成反馈。

## 8. 认知负荷：不能从“记忆约四项”推出四张手牌

### 8.1 NASA-TLX 提供主观负担的六个维度

[NASA Task Load Index](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)用六个分量评估任务负担：心理需求、身体需求、时间需求、表现、努力和挫败。

在 Faust 中，它适合比较同一任务的不同界面版本，例如：

- 原始平铺手牌；
- 自动分类；
- 按仪式筛选合法人物；
- 系统提出少量候选方案；
- 已解决日常任务自动执行。

应保留六个分量而不是只报告总分。自动化可能降低心理需求和努力，却同时降低玩家自评表现或提高挫败；总分会掩盖这种交换。

### 8.2 DRT 能测剩余注意资源，但会干扰主任务

论文 [Assessing Game Interface Workload and Usability](https://doi.org/10.1145/3290688.3290749)让 38 名参与者执行不同负荷的电脑追踪任务，同时响应软件检测反应任务（DRT）。DRT 对任务负荷敏感，但也干扰了主任务表现。

在受控实验中，可以偶尔出现简单刺激，记录：

- 反应延迟；
- 未响应率；
- 主任务正确率变化。

DRT 适合确认界面是否耗尽剩余注意，不适合在正常叙事游玩中长期开启，因为测量本身会改变体验。

### 8.3 工作记忆容量是研究提醒，不是 UI 上限

Cowan 的综述 [The Magical Number 4 in Short-Term Memory](https://pubmed.ncbi.nlm.nih.gov/11515286/)讨论在限制复述和进一步组块化的条件下，注意焦点约能维持四个独立组块。

这不能推出：

- 手牌上限应为四张；
- 所有选择都应四选一；
- 屏幕上超过四个对象一定过载。

熟练玩家会把多张卡按人物、关系、任务和既有方案组块；界面本身也是外部记忆。真正应测的是玩家必须同时维护多少个**独立且不能从界面直接恢复的信息组块**。

### 8.4 视觉杂乱应通过搜索表现测量

研究 [Searching in Clutter](https://www.sciencedirect.com/science/article/pii/S0003687021002751)将 58 名参与者分为动作游戏玩家和非玩家，让其在低杂乱与高杂乱场景中搜索目标，测量反应时间、正确率、注视次数和注视时长。杂乱降低搜索表现并改变视觉行为；专家可能采用不同策略，但没有自动获得整体表现优势。

对卡牌界面的直接启示是记录：

- 目标与干扰项数量；
- 首次注视目标所需时间；
- 总搜索时间；
- 错选和漏选；
- 是否必须反复打开详情；
- 分类、空间位置和视觉相似度如何影响结果。

### 8.5 认知负荷阶段结论

**来源事实：** TLX、DRT、工作记忆和视觉搜索均有成熟方法，但实验任务与叙事卡牌不同。

**设计解释：** 《苏丹》的后期问题不应简化为“普通人最多想四件事”，而应定位为搜索、检索、优先级、重复执行和隐藏依赖共同占用注意。

**待验证假说：** 自动筛选和默认执行会显著减少搜索时间与重复操作，但只有在玩家仍能理解人物后果时才算成功。

## 9. 人物依恋、永久死亡与叙事选择：必须拆开测量

### 9.1 有意义选择不等于即时乐趣

CHI 论文 [Choosing to Help Monsters](https://edoc.unibas.ch/entities/publication/c0880d6c-7f2a-4a68-ac0d-7e3127770f38)先通过质性研究归纳玩家认为有意义的选择特征，再用实验检验 appreciation、enjoyment 和 narrative engagement。研究强调道德、社会和后果特征与选择意义有关，选择意义提高 appreciation。

因此，Faust 不能只问“好不好玩”，还要分别测量：

- 玩家是否理解选择会影响谁；
- 是否觉得后果与自己的决定有关；
- 是否感到道德或关系冲突；
- 是否欣赏这段经历；
- 是否享受当下操作。

### 9.2 永久死亡的意义依赖既有依恋

博士论文 [It's All Fun and Games until Somebody Dies](https://researchrepository.wvu.edu/etd/7614/)调查 394 名在过去一年经历过永久死亡或暂时死亡的玩家。结果支持：永久死亡可以通过对角色的悲伤提高 appreciation，且角色依恋会加强这条路径；并没有得到同样清晰的死亡显著性中介证据。

这说明：

```text
永久死亡本身
≠ 自动产生人物意义

持续关系与依恋
→ 死亡发生
→ 悲伤和不可逆性
→ 更强的意义/欣赏
```

随机、不透明、与玩家选择无关或可以无成本重开的死亡，可能只产生挫败。

### 9.3 人物认同、乐趣和能力感不是同一变量

实验 [Character Customization With Cosmetic Microtransactions in Games](https://pmc.ncbi.nlm.nih.gov/articles/PMC8765231/)让 24 名参与者在自选外观与默认外观条件下完成受控任务。自定义显著提高角色认同：`t(23)=3.391, p=0.003, d=0.692`；乐趣、感知能力和实际表现没有显著提高。

虽然外观自定义不同于长期培养具名人物，它仍证明一个重要方法问题：玩家参与塑造角色可能提高认同，但不能假定乐趣、能力感和表现同步上升。

### 9.4 自适应叙事必须按玩家类型验证

[PaSSAGE](https://ojs.aaai.org/index.php/AIIDE/article/view/18780)根据行为学习玩家偏好，再动态选择故事内容。用户研究表明，自适应故事能提高**部分类型玩家**的娱乐价值，而不是对所有人统一有效。

这对自动推荐人物、仪式或事件的警告是：推荐系统可能帮助目标导向玩家，却让探索型玩家觉得被安排。必须保留固定组或低推荐组作对照，并按玩家行为分层。

### 9.5 事件树结构指标不能替代选择意义

论文 [Choose Your Own Adventure](https://scholarship.claremont.edu/jhm/vol9/iss2/5/)把 40 本互动游戏书转成有向图，统计最长路径、终点数量等结构指标。

Faust 可以计算：

- 分支数和汇合率；
- 路线长度；
- 结局数；
- 瓶颈和不可达节点；
- 人物状态改变的后续节点数量。

但“分支多”不等于“选择有意义”。若所有分支很快汇合、后果不可见或与人物无关，图很复杂也可能没有责任感。

### 9.6 人物与叙事阶段结论

**来源事实：** 选择意义、角色认同、永久死亡悲伤和自适应故事均有实验研究，且结果变量并不一致。

**设计解释：** 人物卡之所以有价值，不是因为它带名字，而是因为同一人物被持续投入核心行动、积累关系与状态，并承担可追悔的后果。

**待验证假说：** 自动化低价值操作后，只要玩家仍亲自决定“哪位具名人物承担后果”，人物依恋和选择意义可以保留；若系统连责任分配也自动完成，体验会显著变弱。

## 10. 遥测与自动测试：怎样让 Faust 自己产生证据

### 10.1 技能水平会改变变量的重要性

PLOS One 研究 [Video Game Telemetry as a Critical Tool in the Study of Complex Skill Learning](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0075129)分析 3360 名即时战略玩家、7 个技能等级，从行为中提取 12 项认知运动、注意和知觉变量。研究发现变量的重要性会随技能等级改变，只比较新手和高手可能误导。

所以 Faust 的测试至少要记录：

- 玩家此前是否接触《苏丹》、P5R、火纹或自走棋；
- 当前原型已玩次数；
- 是否看过教程或设计说明；
- 每轮操作与结果；
- 学习曲线而不只是首次表现。

### 10.2 大样本聚类不能提前替小样本造人格

研究 [A Comparison of Methods for Player Clustering via Behavioral Telemetry](https://arxiv.org/abs/1407.3950)比较 70014 名《魔兽世界》玩家、五年数据上的聚类和 archetypal analysis，强调结果是否可解释、可行动。

Faust 以后可能出现“固定人物保护”“追结局”“囤积”“高自动化接受度”等行为模式，但早期样本不应先给玩家贴类型标签。先记录连续变量，再检查模式是否稳定复现。

### 10.3 自动玩家适合找规则后果，不适合证明情感体验

论文 [Automated Playtesting with Procedural Personas through MCTS](https://arxiv.org/abs/1802.06881)用不同目标启发式的程序化 persona 和 MCTS 自动测试内容。

Faust 可建立少量可审计代理：

- 保命优先；
- 固定人物保护；
- 追即时收益；
- 追特定结局；
- 最少操作；
- 接受随机供给并转型。

它们可以发现不可达内容、单一优势策略和资源死锁，不能证明真人会依恋人物、感到后悔或喜欢自动化。

### 10.4 Faust 最小遥测事件表

| 事件 | 必须记录的字段 | 研究用途 |
|---|---|---|
| `decision_opened` | 玩家、周目、时刻、可见手牌、可见仪式、期限对象 | 重建决策环境 |
| `rite_opened` | rite UID、槽位、合法候选数 | 测量候选组合规模 |
| `card_inspected` | card UID、来源区、停留时长 | 测量搜索与规则确认 |
| `card_assigned` | card UID、slot、是否推荐、是否撤销 | 测量责任分配与错误 |
| `decision_committed` | 动作、总时长、操作数、候选方案数 | 比较界面版本 |
| `auto_action_used` | 自动化类型、建议内容、是否覆盖 | 判断自动化接受度 |
| `resolution_finished` | 结果分布、实际结果、人物状态变化 | 连接配置与后果 |
| `deadline_missed` | 对象、当时界面状态、是否看见提示 | 区分遗忘与取舍 |
| `save_or_reload` | 发生位置、不可逆后果、距结果时间 | 观察追悔和拒绝后果 |
| `session_ended` | 主动退出位置、最后任务、负担问卷 | 分析放弃点 |

所有人物引用必须使用同一运行时 UID，才能判断同一人物如何跨手牌、仪式、校园行动、自动结算和后果持续存在。

### 10.5 最小对照实验

第一轮实验不需要完整游戏，可以让同一批玩家完成结构相同的任务：

| 条件 | 界面/自动化 |
|---|---|
| A | 原始平铺手牌与手动检索 |
| B | 自动分类，但仍由玩家检索和投入 |
| C | 按仪式自动筛选合法人物 |
| D | 系统提出 3—5 个高层方案，玩家决定承担后果的人物 |
| E | 系统连人物分配也自动完成 |

核心因变量：

- 决策时间；
- 卡牌检查和拖拽次数；
- 错误与遗漏；
- NASA-TLX 分量；
- 对结果原因的解释正确率；
- “这是我的决定”感；
- 对人物的责任、后悔和认同；
- 是否愿意继续下一轮。

预期的关键比较不是 A 与 E，而是 C/D 与 E：它用于判断自动化到哪一层开始夺走人物责任。

### 11.2 已经可以确定的结论

1. 《苏丹》的卡牌管理痛点存在，但阈值未知。
2. 静态内容规模不能直接代表运行时认知负担。
3. 《风花雪月》和 P5R 的日程都能被形式化，但只有 P5R 攻略提供了明确的全目标构造性可行解。
4. 《风花雪月》破圈是商业事实；“校园闭环降低关心并学习战棋的动机门槛”是强解释，不是单因果证明。
5. 《酒馆战棋》的模拟、真实聚合和技能分层必须组合使用；它是 Faust 最值得借鉴的研究生态。
6. 血流成河类比能够提出“首次成型后持续运转”的状态模型，不能证明这种结构必然更爽。
7. 自动化应减少检索、重复执行和微观控制，但不能未经测试地接管具名人物的责任分配。

### 11.3 仍然完全没有答案的问题

- Faust 的活跃手牌和仪式规模在什么条件下开始显著增加搜索时间和错误？
- 玩家是否需要看到全部合法人物，还是少量有意义方案就足够？
- 自动推荐如何影响“这是我的决定”感？
- 什么对象应当在首次成型后持续存在？
- 持续运转应产生何种成长、收益和风险？
- 校园培养进入自动行动后，玩家能否从结果看懂此前投资？
- 不同熟练度玩家需要多少解释、预测和自动化？
- 人物死亡、受伤或关系破裂在什么条件下产生意义而非单纯挫败？

## 12. 对 Faust 的阶段性研究结论

### 12.1 不应寻找一个武断的“正确手牌上限”

现有证据不支持 4 张、7 张或任何固定数字。应先控制并测量：

- 屏幕对象数；
- 当前合法候选数；
- 真正不同的高层方案数；
- 搜索和重复操作成本；
- 玩家必须自行记忆的隐藏依赖数。

### 12.2 应先压缩决策面，再讨论删掉多少内容

P5R 证明庞大长期状态可以通过日期和可用性压缩为有限当下选择；《风花雪月》通过月份、行动点、动机和学生名额实现类似压缩；《酒馆战棋》用当轮金币、酒馆供给和场上/手牌边界压缩选择。

因此，Faust 的第一目标不是让世界变小，而是让玩家每次只面对当前真正有关的部分。

### 12.3 自动结算必须成为可观察的模型反馈

酒馆战棋生态说明，自动阶段最有价值的研究方式是：

```text
玩家配置
→ 系统自动执行
→ 输出清楚结果
→ 可比较替代方案
→ 玩家调整下一轮配置
```

如果自动行动只播放不可解释的结果，它减少操作，也同时减少学习。

### 12.4 人物意义必须通过同一实例的持续后果验证

人物依恋研究和此前项目结论共同指向：具名并不足够。人物必须跨行动持续存在，玩家的培养改变其表现，行动结果又回写其伤害、关系、成长和死亡可能。

### 12.5 研究顺序

下一阶段最合理的顺序是：

1. 用无新增内容的任务原型记录《苏丹》式手牌和仪式的基线负担；
2. 加入筛选、推荐和默认执行，做被试内对照；
3. 保留“谁承担后果”的人工决定，验证人物责任是否保留；
4. 再原型化一种“首次成型后持续运转”的结构；
5. 用自动代理检查可达性和优势策略；
6. 用真人测试决定体验，而不是让代理或静态图替玩家回答。

## 15. 最终结论

公开研究并没有替 Faust 设计出答案，但已经把问题边界划得足够清楚：

> 我们不缺更多系统类比，缺的是把现有手牌—仪式—人物循环变成可记录、可模拟、可分层比较的实验对象。

《苏丹的游戏》告诉我们作者空间和管理痛点在哪里；《风花雪月》和 P5R 告诉我们怎样用周期与有限时段压缩长期状态；《酒馆战棋》展示怎样把准备选择、自动执行和数据反馈连成定量闭环；麻将提供随机供给、距离成型和持续运转的状态语言；认知与叙事研究则规定了不能只看胜率、时长或“好不好玩”。

第一轮 Faust 数据研究应检验的不是“自走棋方案是否完整”，而是一个更小、更关键的问题：

> 当系统替玩家完成检索和重复执行、但仍由玩家决定哪位具名人物承担长期后果时，能否同时降低操作与认知负担，并保留理解、责任和追悔？

这项问题得到数据回答后，才有资格继续决定手牌容量、候选方案数量、持续结构以及自动化程度。
